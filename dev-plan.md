Dev plan — Japan Trip Planner v2

Цель
- Преобразовать приложение из заметочника в персональный путеводитель по поездке.
- Пересобрать JSON-конфиг как финальную версию v2 и расширить модель данных.
- Сохранить текущую архитектуру Angular + Taiga UI, но добавить более содержательные поля и улучшить отображение маршрута.

План правок

1. Обновить модель данных
   - Добавить новый тип `TripPoint` (= `ScheduleItem`) в `src/app/models.ts`.
   - Расширить поля маршрута:
     - `durationMinutes?: number`
     - `type?: 'museum' | 'shopping' | 'food' | 'transport' | 'viewpoint' | 'temple' | string`
     - `priority?: number | 'must' | 'high' | 'medium' | 'low'`
     - `reservationRequired?: boolean`
     - `completed?: boolean`
     - `weatherDependent?: boolean`
     - `estimatedCost?: number`
     - `tags?: string[]`
     - `status?: 'planned' | 'visited' | 'skipped'`
     - `personalNote?: string`
   - Сохранить `googleMapsUrl` и `photoUrl`.

2. Пересоздать конфиг `src/assets/trip-config.json`
   - Сделать полноценный маршрут для всех дней поездки.
   - Унести все важные точки и актуальные изменения:
     - Gotokuji, Yanaka, KITTE Garden, Ochanomizu, Nakano, отправка багажа, скорректированные планы по Universal и Нара.
   - Добавить детальные описания, типы, длительность, стоимость, приоритеты, бронь и теги.
   - Сохранить структуру `days[].schedule[]` для обратной совместимости с текущими компонентами.

3. Обновить UI для новых полей
   - В `ScheduleItemComponent` отобразить:
     - тип, длительность, стоимость, приоритет, статус,
     - требования к бронированию, зависимость от погоды,
     - ссылку на карту, фото, заметку.
   - В `DayCardComponent` сохранить день недели и шапку дня.

4. Обновить документацию
   - Обновить `README.md`: ссылка на GitHub Pages, информация о документации.
   - Обновить `docs/dev-plan.md`: текущий статус и подробный план.
   - (опционально) Обновить `agents.md` с новыми полями модели.

5. Проверить
   - Собрать проект `npm run build`.
   - Запустить `ng serve` и убедиться, что новые данные отрисовываются.

Дополнительные идеи (после v2)
- Фильтрация маршрута по типу/тегам/приоритету.
- Состояние мест: planned/visited/skipped.
- Локальные заметки `personalNote` для дневника поездки.
- Интерактивная карта с точками.

Примечание
- Я сохраню текущий формат `days[].schedule[]`, чтобы не ломать компоненты.
- Тем не менее внутренняя модель будет расширена и позволит легко перейти к истинному «Trip Guide».
